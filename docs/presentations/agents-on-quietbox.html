The problem

Code sessions on gpt-oss-20b worked for hours, then stopped mid-task

One real session made 513 tool calls that worked. At 85–87K tokens of context, the model started writing its tool calls as plain text instead of making them:

assistantcommentary to=functions.Read json{"file_path":"desktop/src/pages/Code.tsx","line_start":470,"line_end":520}

The agent passed that text on as a finished reply, so nothing ran and the turn ended. In the same stretch it invented a Search tool and line_start parameters.

Root causes

  • Format drift late in long sessions. gpt-oss's own tool-call syntax ("harmony") leaks as text once context is long.
  • No safety net in our translator between Claude Code's API and vLLM's.
  • Sessions never compacted early. They ran toward the 131K window, deep into the range where the model degrades.

The model server was configured correctly: the same requests, made directly, parsed 10 of 10 times.

Hardware lens

On 4 Blackhole chips, decode speed is set by fixed cost per layer, not bandwidth

A roofline planner, calibrated against two runs measured on this QuietBox, decode tokens/s per user:

… with multi-token prediction~390–

What that means for model choice

  • Mixture-of-experts with few active, 4-bit experts fits the hardware. gpt-oss-20b already is that.
  • Fewer, wider layers beat deep, narrow ones: each layer pays dispatch plus Ethernet collectives.
  • Dense models are the wrong fight against HBM GPUs on decode.
  • Prefix caching matters more than raw decode for agents. Code re-reads its context about 160 tokens for every one it writes.

Planner rows without a measurement are projections. Quality isn't modelled.

Measured

Valid tool calls hold near 86% up to 64K tokens, then fall to about 70%

Claude Code-shaped requests through our own translator, 50 per size, on gpt-oss-20b on the box. Whiskers are 95% intervals.

  • No size reached 95% valid. So Code keeps compacting at 64K on this model, now backed by data rather than a guess.

Fixed in the agent

A safety net between Claude Code and the model, that never guesses

What the translator does now

  • Rescues tool calls written as text and turns them back into real calls, streamed or not.
  • Checks every call against the tool's schema: name, required fields, types, unknown fields.
  • Repairs only what can't change meaning: tool-name case, leftover gpt-oss syntax on a real name, "470" for a number, JSON in a string.
  • Ends the turn cleanly when vLLM says "tool call" but sends none.
  • Counts calls as valid, repaired, invalid or leaked, per model.

What it deliberately doesn't do

  • No renaming parameters (line_start → offset). That would change what a call does. Claude Code's error tells the model, and it retries.
  • No forcing a tool call on every turn. An agent has to be able to answer in plain text.

Compaction

Sessions summarize at 64K tokens, or at the window a model's measured check-up recommends. A live meter in Code shows how close a session is.

Finding for upstream

vLLM doesn't hold gpt-oss tool calls to their schema, in any mode

tool_choiceArgs fit schemaWhat else we saw
auto92%Today's setting
auto + strict88%Strict flag has no effect
required96%3 of 12 replies were plain text anyway
named tool88%7 of 24 called a different tool

144 requests on gpt-oss-20b, vLLM 0.26.0.dev4, 24 per mode on everyday tasks. line_start came back even with a named Read tool. response_format with a JSON schema is enforced, so the gap is in vLLM's gpt-oss tool path.

Decision

  • Keep auto, the only mode that lets the agent answer in text.
  • Check in our translator, where we control it.
  • Raise it with vLLM, with the script and numbers in docs/notes/tool-call-constrained-decoding.md.

Latency was 6–10 s per request in every mode; it tracks output length, not mode.

Remote access

How a computer connects to the box

Find

The app finds the box on the local network (mDNS) and reads its TLS certificate.

Prove

A pairing code shown on the box, or an SSH key the computer already has. Passwords no longer work over SSH.

Cross-check

Over SSH the box reports its certificate again; a mismatch stops pairing as a possible impostor.

Issue

A 256-bit token for that one device, stored on the box only as a hash.

Use

Every request is HTTPS (TLS 1.3, AES-256-GCM) pinned to that box's exact certificate.

Already strong

  • Certificate pinning: no certificate authority can vouch for an impostor.
  • Modern SSH, including post-quantum key exchange. Passwords never stored.
  • iPhone keeps its token in the iOS Keychain.

Below enterprise expectations, before this work

  • Sessions never expired and could only be revoked all at once.
  • SSH password login open to the network; no firewall, no lockout.
  • Desktop token in a plain file. No SSO or MFA.

Open decisions

What needs a call before a wider rollout

Security

  • Store apps on the LAN without login: Langflow (its auto-login can run code), Flowise, n8n, LightRAG. Box-only by default, or behind the gateway?
  • Routines can still let web text drive memory and pre-approved actions.
  • After a web read, a model could leak data through the URL of a later fetch.
  • SSO and MFA for company-managed boxes.

Product and engineering

  • Where this lands: all of it is local commits on jberkowitz/mobile-voice; nothing is pushed.
  • Not yet verified live: iOS build, macOS keychain, Electron click-through on another computer, the explain route end to end.
  • Cached-token numbers need --enable-prompt-tokens-details on the model server.
  • Recovery isn't scored: the eval grades first replies, not Claude Code's retry.

The biggest remaining levers

Speculative decoding for gpt-oss

The planner's biggest single lever, about 2× decode. Needs a small trained draft head (GPU time) and serving support.

A second model alongside

A drafter, embeddings or router sharing the box. Blocked on chip leasing (gozer) allowing a companion slot.

Score recovery, not just first replies

Extend the reliability eval to multi-turn sessions so compaction targets what users actually feel.

Prefix caching for Code by default

Route Code to a model whose server caches prefixes; the picker already shows which do.

Upstream the vLLM gap

Schema-constrained tool arguments for gpt-oss would remove most invalid calls at the source.

Enterprise identity

SSO, MFA and audit export on top of the per-device sessions.
