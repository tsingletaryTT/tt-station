# Linux tray app and main window: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust tray app (`tt-station-tray`) with a simple start/stop menu and a main window for stations, models and run options, plus the agent changes that let a remote station accept run options.

**Architecture:** Shared option types and validation live in `libttstation` so the agent, the client and the UI use one definition. The agent gains `options` on `POST /run`, a `GET /run/schema` route, and a `tt` serving backend. The tray crate talks to stations through one `Station` trait with a local implementation (`tt --json`) and a remote one (agent client). The menu is built from a pure data model, then rendered through `ksni` (SNI).

**Tech Stack:** Rust 2021 workspace (axum 0.8, tokio, serde, reqwest), `ksni` (SNI tray), `zbus` (D-Bus), `gtk4-rs` (window), stdlib/`assert_cmd` tests, `mock-box` for no-hardware tests.

**Spec:** `docs/superpowers/specs/2026-10-05-linux-tray-design.md`

## Global Constraints

- **Never name anything `tt`.** Binaries are `tt-station`, `tt-station-agentd`, `tt-station-tray`. The official `tt` is called, never shadowed.
- The agent accepts only a `tt` whose `--version` output is `tt <semver>` (same rule as `libttstation::local_device` / `tt-station local`).
- `POST /run` stays backward compatible: `{"model": ".."}` and `{"model": "..", "force": true}` keep working unchanged.
- The agent never passes raw argv from a client. Run options are validated against an allowlist before any process starts.
- Tool and service names are not hardcoded in more than one place (memory: configurable CLI tool names). Reuse `ToolNames` in `crates/tt-station/src/console/names.rs` for the CLI and add the tray's names beside it.
- Every hardware-touching command goes through `gozer run --chips 1 --who "claude:linux-tray" --reason "<why>" -- <cmd>`. `import ttnn` also counts. Honour `TT_VISIBLE_DEVICES`.
- Terminal and TUI output uses left and bottom bars only, never right-side borders.
- Comments are thorough and kept honest. Bump the workspace version with `scripts/bump-version.sh` once, in Task 10.
- Plain English in docs and commit messages: state the finding, no "X, not Y" framing, no aphoristic closers.
- Default branch is `main`. Work stays on `feat/linux-tray`.

## Review Focus

1. **An option value that smuggles a flag or shell syntax** (`"4096 --privileged"`, `"x; rm"`, a newline, a leading `-`, an empty string): rejected with the field name, and nothing starts. Pinned in Task 1.
2. **An old client posts `{"model": ".."}` with no `options`**: behaves as today. Pinned in Task 2.
3. **A backend that cannot honour options** (`runpy`, `docker`) receives a non-empty `options`: returns 400 naming the backend, never silently ignores them. Pinned in Task 2.
4. **`tt` is missing, or is a stale pre-rename binary**: the `tt` backend refuses at construction or first use with a message, and `LocalStation` reports it. Pinned in Tasks 3 and 5.
5. **Station goes offline mid-poll, or a 409 (chips held) comes back from Run**: the menu model shows "offline" or the holder text, and Stop and Restart are not offered for a station that is not serving. Pinned in Task 7.

- [ ] **Step 4: Implement**

Implementation rules the code must follow (write it fully, commented):
- `from_value` first checks the top-level keys against `["device","port","profile","offline","workflow","vllm_args"]` and returns `OptionError{field: <key>, ..}` for any other key, then deserializes with serde (map serde errors to `OptionError` whose `field` is the offending key when it can be found, else `"options"`), then calls `validate()`.
- `validate`: `device` matches `^[a-z0-9]{2,16}$`; `profile` matches `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`; `port` is `1024..=65535`; every vllm `flag` is in `VLLM_ALLOWLIST`; its `value` obeys its `VllmKind` (`Int{min,max}`, `Bool`, `Token` = `^[a-z0-9][a-z0-9_-]{0,39}$`); no flag appears twice. Use plain char loops, not a regex crate, to avoid a new dependency.
- `VLLM_ALLOWLIST` starts with: `max-model-len` Int 1..=1048576, `max-num-seqs` Int 1..=1024, `max-num-batched-tokens` Int 1..=1048576, `block-size` Int 1..=1024, `enable-auto-tool-choice` Bool, `tool-call-parser` Token, `reasoning-parser` Token.
- `to_serve_args` emits in this fixed order: device, port, profile, offline, workflow, then `"--"` followed by each vllm flag as `--<flag>` and its value, and emits no `"--"` when `vllm_args` is empty.
- `run_schema` builds one `OptionSpec` per top-level option and one per allowlisted flag named `vllm:<flag>`. Mark `vllm:*` entries `applies_to: ["bundle"]` until Task 3 step 2 proves otherwise for catalog models.

pub struct StationId(pub String);          // "local" or "<host>:<port>"
